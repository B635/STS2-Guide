## 实施报告（2026-10-02）

- **提取器 v4**：纳入能力类（`Models.Powers`，265 种，类名去掉 `Power` 与目录一一对应）；解码卡牌构造函数的费用与类型、`get_CanonicalTags`，
  与目录 595 张牌的费用、类型全部一致；`--enum` 列出枚举值。
- **初分修正**：`AfterRoomEntered` 在进入战斗房间时施加能力（金刚杵、翡翠之剑、光滑石头等 9 件）被误判为局外，改为在调用战斗命令时归基线。
- **遗物事实 298/298**：111 件按结构判为无关（只有局外钩子、进房间不调用战斗命令；有防回归测试）；187 件由 5 个审核 Agent 逐件读 IL 写成，
  统一校验（`scripts/merge_fact_reviews.py`：条目存在、指纹一致、词汇合规）后合并；我对照 IL 抽查苦无、金刚杵等无误。
  审核中发现的代码与目录描述不一致（假打击人偶按标签、威吓头盔按实付能量、面包第 1 回合失去 2 能量、镶宝石面具仅当回合免费等）均以代码为准写入证据。
  只改变“提供哪些奖励”的遗物归无关；入牌组时改变卡牌的（几个蛋、菲涅尔透镜）用 `card_added_to_deck`，模型对候选按升级后计分。
- **评分引擎** `advisor/deck_mechanics.py`：卡牌与遗物统一换算为每回合期望——事件频率（打出/耗竭/弃牌/洗牌/受伤/敌人死亡）、
  每 N 次与计数范围（回合内按泊松）、每回合/每场首次、条件概率（无格挡、剩余手牌、手牌为空、本回合未打出某类牌等）、回合排程（第 n 回合、每 n 回合、第 n 回合起），
  抽牌与能量反馈迭代；战斗开始的力量计入前期输出，逐回合增长计入成长。不认识的过滤、条件、字段一律视为不支持并披露（审查发现原实现会忽略未知过滤）。

## 独立审查与返修（/code-review，两轴并行）

- 规格轴抽查 8 件遗物（船锚、灯笼、卡戎之灰、手里剑、冰冻蛋、准备背包、开心小花、威吓头盔）对照 IL，全部一致。
- 规范轴发现并已返修（引擎整体重写）：`count: "all"` 导致崩溃（数量必须为数字，否则不支持）；非“打出牌”时机的卡牌过滤被丢弃（只允许战斗类型过滤）；
  号角海螺精英限定被算进每场（修正按战斗类型生效）；修正的未知字段被忽略（逐种修正限定字段）；过滤值为列表时永不匹配（判为不支持）；
  卡牌效果只校验种类（统一 `effect_unsupported`：字段、数值、目标）；缺药水信息被当成“无药水”（未知即缺口）；引擎缺口未计入数据完整度；
  能力牌每回合可打出（改为每场一次）；X 费重复计算能量（改为使用剩余能量）；“每 N 次 + 上限”与按战斗计数改用泊松期望；第 N 回合获得的力量按剩余回合折算；
  中毒层数大于回合数时公式修正；`min_cost` 按实付能量；私有标记与私有导入去除（公开 `unsupported_reason`）；合并工具校验修正名称。
- 规格轴发现并已返修：影响“拿/跳过”本身的遗物（佩尔之翼、五环之书、幸运鱼、暗石护符）不再归无关，记录为 `card_reward_choice` 并在选牌时披露；
  佩尔之翼换得遗物的价值登记为无法得知；宾邦（复制加入的牌）由“静默丢弃”改为不支持并披露。
