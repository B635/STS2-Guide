## 实施报告（2026-10-01）

- `advisor/golden_set.py`：局面只保存**评分视图**（schema、事件类型、游戏版本、run、序号、决策 ID、路线偏好、状态、候选、
  决策上下文、父决策、地图）；协议外壳由框架以明确标记补齐（全零哈希、`golden-set` 生产者），不伪造游戏数据。
  经处理器公开的 `build_world` / `build_card_reward_request`（原私有方法改为公开，调用点同步）与 `PolicyRegistry` 运行任一已登记版本。
- 报告分“已确认 / 全部”两级统计最佳选择命中率与明显错误排第一次数，并逐局面列出警告（`reconstructed`、`map_context_missing`）。
- `scripts/eval_golden_set.py`（运行与存档）、`scripts/add_golden_situation.py`（把记录器快照加为草稿局面，写入前校验）。
- 标准答案集 `data/golden_set/card_reward.json` 两个 IRONCLAD 局面，标签来自用户真机实际选择：
  - seq 125（重建：牌组/遗物/层数/生命/金币为真机观测，药水与遗物计数沿用 seq 142，路线未知）：用户选择**跳过**；草稿把挑衅列为明显错误候选。
  - seq 142（真实快照）：用户选择**无情猛攻**。
- v1 基准（`data/golden_set/reports/v1.json`，均为草稿标签）：命中 0/2，明显错误排第一 1（挑衅）。
- 测试：`tests/test_golden_set.py` 6 项（使用协议示例事件的内置夹具，不依赖已提交数据的位置）；完整 Python 638 项 / 51.9 秒 / OK。
- **待用户**：确认或修改两个局面的 best / obvious_errors；之后用 `add_golden_situation.py` 补充其他角色局面。

## 独立审查（/code-review，两轴并行）

- 规范轴：跨模块调用私有方法 → 改为公开构建方法；局面数据含非评分字段 → 评分视图；`lambda` 包装去掉；
  测试依赖已提交数据位置与跨类属性 → 内置夹具；缺失候选 ID 不再被转成字符串 `"None"`。与旧 `advisor/evaluation.py`
  的分工：旧框架是 v1 的断言式合成场景，新框架是真实局面的版本对比；后续票统一使用新框架。
- 规格轴：明显错误未标 → 草稿提出挑衅；缺字段不报告 → 评分视图缺字段即报错、局面警告；无快照转换路径 → 新增脚本；
  草稿与确认混算 → 分级统计；重建局面冒充完整快照 → 外壳改为明确标记。版本表未从注册表派生：注册表每种决策只容纳一个策略，
  版本对比由本模块的版本表承担，票 03 在此登记 v2。
