## 必须修复或补齐的缺口

### F1 / 阻断：实体 ID 推导与真实目录不一致

证据：`RunStateReader.ReadDecisionOption`、`ReadPotions` 等仍调用 `StableIds.FromType`，
后者剥离类型后缀，并只在小写/数字与大写之间添加下划线。`RelationalRepository.find_entity`
按 external_id 或名称匹配；`RoutePolicy` 遇到未知药水后记 gap 并跳过其支持贡献。

使用已有本机 `ModelDb.GetEntry(Type)` 探针输出与当前目录交叉核对，只纳入目录中存在的
顶层实体，排除编译器生成的嵌套类型。在 cards/potions/relics 三类对照中发现
**2 张卡牌、27 种药水不一致**，遗物未在本次对照中发现不一致。示例：

| 类型 | 当前推导 | 游戏条目 / 目录 ID |
|---|---|---|
| SpeedPotion | SPEED | SPEED_POTION |
| FairyInABottle | FAIRY_IN_ABOTTLE | FAIRY_IN_A_BOTTLE |
| ExpectAFight | EXPECT_AFIGHT | EXPECT_A_FIGHT |
| IAmInvincible | IAM_INVINCIBLE | I_AM_INVINCIBLE |

输入探针文件为本机忽略的 `build/task013-model-entries.json`；历史输出混有日志和嵌套类型，
不能直接拿原始条目数当覆盖率。当前程序集 hash 与候选一致，但这不是本轮重新真机采集。

规格要求：以经本机程序集验证的模型稳定身份作为生产 ID；修复所有范围内受影响的
读取入口，不靠数据库模糊匹配或补零散别名掩盖问题。增加真实导出 ID → 发行 SQLite →
策略贡献的跨边界回归。验证未知内容仍诚实降级，而非强行匹配成别的实体。

### F2 / 已确认体验待实现：不可用状态没有区分原因

证据：`ContextDrawer.Render` 对空分数统一显示 `--`；Card/Route 的文件缺失、读取失败、
匹配失败都走 Invalidate。当前没有落实第 2.1 节约定的简短状态说明。

规格要求：区分等待、必要数据缺失与一般不可用；只能展示有依据的原因。恢复后自动
更新，不留下失效分数、高亮或路线。未支持场景与版本不兼容遵循已经确认的规则。

专项风险：Card/Route 轮询在 advice 文件时间戳不变时直接返回，不独立判断后台存活。
正常 Controller 清理已存在；若整个 Guide 进程异常消失且文件残留，不能仅靠文件存在
证明当前连接正常。此为源码发现的待复现路径，不是本轮真机确认的故障。下一规格须
覆盖该反例，并区分“同一局面结果仍有效”和“后台已断连”；不能按建议文件年龄直接
认定结果失效，也不能把残留 runtime-status 文件当作活跃进程证明。
