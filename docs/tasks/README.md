# STS2 Guide 任务协作流程

本目录是 Codex 与 DeepSeek 跨会话协作的唯一任务通道。聊天内容不能替代任务单。

## 角色

- 用户：产品决策者，确认体验、范围和取舍。
- Codex：PM 与架构审查者，维护规格、创建任务、验收实现、查缺补漏。
- DeepSeek：实现工程师，只实现当前任务并补充测试，不自行扩展产品范围。

## 当前任务入口

所有实现会话首先读取 [`current.md`](current.md)。

- `状态：无任务`：不得修改代码；
- `状态：待实现`：DeepSeek 可以实现任务单；
- `状态：实施中`：说明实现尚未交付；
- `状态：待审查`：DeepSeek 已交付，等待 Codex 审查，不应继续改动；
- `状态：需修复`：DeepSeek 只处理 Codex 列出的审查问题；
- `状态：已验收`：任务结束，不得继续修改。

`current.md` 只保存状态和一个任务单链接。完整内容使用
`TASK-NNN-short-name.md`，格式见 [`TEMPLATE.md`](TEMPLATE.md)。

## 标准流程

1. 用户向 Codex 提出需求或问题；
2. Codex 判断优先级，必要时先更新 `docs/product-spec.md`；
3. Codex 创建任务单并把 `current.md` 设为 `待实现`；
4. DeepSeek 阅读 `AGENTS.md`、产品规格、项目状态和任务单；
5. DeepSeek 只修改任务范围内的代码与测试；
6. DeepSeek 在任务单填写实施报告，把任务和 `current.md` 更新为 `待审查`；
7. Codex 独立检查 diff、运行必要测试并填写审查结论；
8. 不通过时设为 `需修复`；通过后设为 `已验收`，并按真实证据更新项目状态。

常用自动审查入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\run_p0_review.ps1
```

该脚本只运行本地自动检查，不安装 Mod、不启动游戏、不替代真机回归。

## 实施报告要求

DeepSeek 必须记录：

- 修改过的文件及每个文件的目的；
- 实际执行的命令和完整结果摘要；
- 未运行的测试及原因；
- 是否完成编译、安装和真机验证；
- 已知风险、假设与未解决问题。

不得用“应该可用”“理论完成”代替验证证据。不得伪造命令输出，也不得把自动测试通过
写成真机验证完成。

## 范围控制

- 没有当前任务时，不因代码中的 TODO、旧文档或聊天内容自行修改项目；
- 发现任务外问题时，只写入实施报告的“范围外发现”，等待 Codex 决定；
- 需要改变协议时，必须在任务范围中明确列出 schema、示例、生产者、消费者和测试；
- 需要改变产品行为时，必须先由 Codex 更新产品规格；
- 不复制参考项目的代码、权重、流派表或数据文件。
