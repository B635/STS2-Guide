### S1. 数据身份修复（F1，优先于评分和 UI）

读取本机实际版本，阅读 API 参考文档，用当前程序集核实模型稳定身份接口。先复现
SpeedPotion、FairyInABottle、ExpectAFight、IAmInvincible 四类反例，再核对范围内所有
实体读取入口；不能只修这四个名字。排除编译器生成的嵌套类型，保留来源与验证方式。
修复真实 ID → 生产导出 → 发行 SQLite → 现有策略输入链路；不调权重，不新增模糊别名。
增加行为回归证明已知药水/卡牌不再报错误的 unknown，且有结构化效果的资源进入现有
因子；未知实体仍安全降级。若旧当前局缓存含错误 ID，由新完整快照替换，不改游戏存档。

### S2. 不可用提示与恢复（F2）

先复现等待、缺文件、损坏 JSON、身份不匹配、策略空分数和有效结果恢复，再补公共抽屉
的简短状态说明，选牌与路线保持一致。具体原因必须有证据，不能把“没有文件”写成
“Host 未启动”。未支持场景隐藏，版本不匹配停止推荐并在托盘说明。

区分 Controller 正常清理、Worker 意外退出和整个后台异常消失。后者是源码风险，先
建立可复现证据，不直接假设所有退出路径都有同一故障。确定最小本地活跃性判断方式，
记录检测周期和最大检测延迟，并用可控测试验证边界；建议文件长期未变不能直接判过期。
失效后清除分数、高亮和地图线，恢复只接纳匹配当前决策的结果。不得新增通用监控平台。

如需调整跨进程字段，先明确状态契约及其权威来源，再同步协议、示例、生产者、消费者、
版本身份和测试；不能通过 UI 文案猜测实际连接状态。

### S3. 自动回归、构建与独立代码审查（F5）

复用已有发行数据库、策略、文件桥、Controller 测试边界，补 S1/S2 的正反例。
执行完整 Python 测试和 Mod/PCK 编译，再进行最终安装包构建、启动检查与 payload 审计。
保留旧测试中仍有效的行为覆盖；只有与当前规格确实冲突的断言才替换，并说明理由。
源码字符串断言不能替代真实模型映射或 Godot 时序测试。独立审查实际 diff 和证据，
有阻断则返修复测；通过后转待真机验收，不直接写已验收。

### S4. 最终安装包与五角色真机（F3）

先盘点带版本的可复用证据，再补缺项；旧版本结果不替代当前版本。通过安装向导验证
普通玩家流程，游戏从 Steam 启动，Guide 从安装入口启动，不依赖 Python、终端或测试 Mod。
分别记录五角色的通用规则、角色机制和第一幕 Card/Route 场景；共用生命周期与窗口测试
可以使用代表场景，但不得把战士单角色记录写成五角色通过。

覆盖双启动顺序、重复启动、选牌/跳过、路线三模式和实际偏离后重算、地图滚动与真实
窗口尺寸变化、奖励未决和进入下一节点后的保存继续、关闭游戏待机、重新开游戏恢复和
完全退出。界面与协议记录相互印证；正常静止的有效决策不因等待较久被误清除。
故障测试应使用隔离/可恢复的测试环境，不删除用户存档，不擅自放弃当前局。

### S5. 材料收口与独立试装（F4）
