## 范围

- 只复盘单局。任何游戏版本的局都收：资料库没有的卡牌或 Boss 就跳过该决定，报告开头注明版本与未评数量。中途放弃的局与多人局不收。
- v1 覆盖：选牌、商店买或离开；休息点只进附录。
- 两层输出：
  - “值得想一想”（严格标记，最多 5 条，按分差由大到小）：引擎首选与玩家选择不同；两者都完整计分；引擎信心不是低；分差 ≥ 2 分或超过该幕的 pick margin。分差只比牌组本身的分数，**不含**跳过门槛（pick margin 只作为判定门槛，不计入分差）。
  - 附录：其余所有决定的完整表格。
- 措辞：“引擎认为 X 比你选的 Y 高 N 分，主要因为…”，不写“失误”。报告开头说明引擎与玩家一致率约 40%。
- 没有严格标记的局：照实写“这局没有引擎有把握的分歧”，不跑 Agent。
- 休息点：升级价值只算得到下限，251/260 次信心为低，因此只进附录并注明；引擎不改（已知限制）。
- 不用 RAG：每句话都必须能对上工具结果。

## 架构

1. 预处理（程序）：用引擎重算整局，列出严格标记并排序。
2. 每条标记一个独立 Agent 小循环（上限 6 次工具调用）。工具：
   - 决策细节（选项、分数、信心、缺口）；
   - 两个选项逐维度比较；
   - 当时的牌组与遗物；
   - 卡牌／遗物事实；
   - 敏感度测试（“如果当时…”）：改动当时的牌组后重算同一个决定。只允许本局真实出现过的东西：删牌组里的牌、加之前出现过的选项、升级牌组里的牌。
3. Agent 以结构化 JSON 交出（不写 HTML）；验证器用程序检查：标记存在且是严格标记、数字与卡名遗物名出现在引用的工具结果中、原因是工具结果里差距最大的几项、无禁用词。不通过则把错误清单送回修一次，仍不通过就删掉该条并在报告注明。
4. 最后一次模型调用只根据已验证条目写一句话总结。
- 技术：Python MCP 服务器（stdio，官方 `mcp` 包）；TS 端自写 Agent 循环：`openai` 包（baseURL 指向 DeepSeek）+ `@modelcontextprotocol/sdk` + `zod`。不用 LangGraph／Vercel AI SDK（流程固定几步，框架没有好处）。
- 模型：`deepseek-flash`（主线），`deepseek-v4-pro` 只用于比较（2026-11 官方文档：两者都支持工具调用与 JSON 输出）。密钥在环境变量 `DEEPSEEK_API_KEY`。
- 输出：CLI 生成简体中文精简 HTML 报告（单文件，附评分按钮和“复制评分”）；每次执行写一份 JSONL trace（模型调用、工具调用、token、延迟、费用、验证结果），`coach trace` 生成 HTML 时间轴。

## 评估

- 数据：历史 43 局单人局（2026-11-01 量测：严格条件下每局中位数 2 条，21% 的局为 0 条；98 条里 89 条是选牌）。
- 切分：开发集 10 局（只用它调 prompt）；测试集 15 局（按角色分层，含 3 局 0.111.0，事先固定，最后只跑一次）；其余局只跑自动指标。
- 指标：
  1. 有没有编造（自动，目标 100%）；
  2. 该点的有没有点到（自动）；
  3. 用户本人评分（有用／没用／引擎错了），先按 1 位评分者设计，朋友以后可用同一格式加入；
  4. flash 与 pro 比较（正确率、评分、成本），在测试集上做。
- 可选加分项（有余力才做）：LLM 裁判抽查说明句，并与人工评分比对一致率。
- 数据存放：朋友的对局与评分只放本机（gitignore）；repo 只放汇总数字、用户自己的评估对局和录下的模型输出（不用 API 密钥也能重算指标 1、2）。引用朋友备注前先问本人。
